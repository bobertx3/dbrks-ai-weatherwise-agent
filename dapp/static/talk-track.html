Before you demo

Who gets the email and the SMS?
By default, the demo owner: email robert.leach@databricks.com, SMS (301) 908-5817. To send to yourself, put your details in the prompt: Send the escalation email to you@company.com and text the summary to +15551234567.
  • Several emails work: separate them with commas.
  • "Email me" means the default address, not you. Always type yours.
  • Phone: use the full number, ideally with +1.
  • The agent sends without asking for confirmation, so check the prompt first.
The agent is slow or errors on the first question
The serving endpoint scales to zero when idle. The first request after a quiet period can take a few minutes while it starts. Warm it up before the demo (step 1). After that, answers take about 10–45 seconds, and the steps stream in while it works.
How do I reset between runs?
Click ↻ in the agent panel for a fresh chat. The agent only sees the current conversation.

About the data

Is the data real?
Shipments, products, hospitals, suppliers and SOPs are synthetic. Product names are fictional but modeled on real temperature-sensitive devices. Supplier contacts and phone numbers (555) are made up, and the agent never emails suppliers. Weather is live from the Open-Meteo API (current conditions plus a 7-day forecast).
What dates is the story built around?
The data is set to a demo date of Nov 19, 2026. The NYC headline shipments (SHP-30001 to 30004) are STAT, with surgery on Nov 20 and delayed arrival on Nov 21. "Tomorrow" in the starter prompts lines up on Nov 19. On other days, ask about shipments "at risk" without a date. To move the story, change DEMO_DATE in data/generate_synthetic_data.py and rerun the setup job.
What does STAT mean?
The shipment is needed for a scheduled procedure, so it ships immediately. Priority (STAT / Urgent / Routine) comes from the hospital order. In this synthetic data it's generated alongside the surgery date. The agent ranks STAT first.
Why is a −30°F reading a problem?
Frozen products have negative ranges. A cryopreserved bone graft must stay between −112°F and −40°F, so −30.7°F is 9.3°F warmer than its limit: it's starting to thaw. Frozen products ship on dry ice, so the agent judges them on sensor reading and delay, not outdoor weather.

How the agent decides

How is risk decided?
  • Out of range now (sensor outside the product's range) → AT_RISK, whatever the weather.
  • Forecast on the arrival day vs the product's range: gap ≥ 20°F → AT_RISK, 10–19°F → BORDERLINE, <10°F → not at risk.
  • Surgery at risk → arrival after the procedure date.
The temperature gap is a Unity Catalog SQL function ("rules, not AI"). The LLM orchestrates and explains.
Why doesn't it mention backup stock or lot expiry?
For execs, "at risk" answers stay short: temperature issues and surgery impact only. Ask for more: "Find backup stock for the at-risk shipments", or use Genie for lot expiry and inventory questions.
Known quirks to steer around
  • "In transit" is also a shipment status. Say "headed to NYC", or the agent may skip Delayed shipments (the headline stories).
  • "At risk tomorrow" means arriving tomorrow. Without a date it covers everything still moving.
  • In the temperature-gap step, the response is an absolute value (no minus sign), so safe and unsafe gaps look alike. Don't open that step's details unless asked.

Platform questions

Which LLM, and how is it governed?
GPT 5.6, called through a Unity AI Gateway model service (bldemos.agentbricks_weatherwise.weatherwise_llm). LLM calls run as a dedicated service principal with EXECUTE on that service, with no personal token. Every call is logged to the inference table weatherwise_llm_payload. Tools (UC functions, Vector Search) use Model Serving's automatic auth passthrough.

Agent vs Genie: which do I use?
Agent: multi-step work that takes action (weather, SOPs, email, SMS). Genie: ad-hoc questions about the data, with the SQL shown. Both use the same Unity Catalog tables and metric view.
How do I rebuild or redeploy it?
See the repo README. In short: databricks bundle deploy, then bundle run setup (data + semantics), bundle run agent_eval (register and deploy the agent) and bundle run weatherwise_chatapp (app). Re-sync Lakebase with scripts/lakebase_resync.sh.
